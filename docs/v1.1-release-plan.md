# v1.1 Release Plan — Multi-profile + Claude

## Goals

1. Support multiple candidates/profiles with chat-only onboarding (no coding).
2. Bind each tailor to a `profile_id` so concurrent agents cannot cross profiles via a shared “active” pointer.
3. Depersonalize shipped skill/agent/scripts (no Mike URL/PDF hardcodes).
4. Publish to npmjs and verify Claude Code install via CLI.

## Design decisions (locked)

| Topic | Decision |
|--------|----------|
| Profile binding | **`state.profile_id` is source of truth** for an in-progress tailor |
| Default profile | Optional `{USER_ROOT}/config.json` → `defaultProfileId` for **new** unnamed sessions only |
| Layout | `{USER_ROOT}/profiles/{id}/profile.json` + `{USER_ROOT}/tailors/{tailor-id}/` |
| Concurrent agents | Safe: each tailor carries its own `profile_id`; never re-resolve default mid-session |
| Onboarding | Chat: paste/PDF/DOCX → extract → Q&A → write profile → set default if first |
| Claude paths | `{PLATFORM_ROOT}=~/.claude`, `{USER_ROOT}=~/.claude/resume-tailor`, `{SKILL_ROOT}=~/.claude/skills/resume-tailor` |

## Workstreams

### A. Depersonalize
- Remove hardcoded portfolio/LinkedIn from `export-pdf.mjs`, `bin/cli.mjs`, `SKILL.md`, research examples where they imply a single person.
- PDF filenames: `{LastName}_Resume_{Role}_{Company}_{Date}.pdf` from `basics.name`.

### B. Multi-profile
- Document + agent rules for list/switch-default/onboard/use-named-profile.
- `profile_id` on state schema (required for new states; legacy without it still validates with warning path in docs).
- Prefer profile path: `profiles/{id}/profile.json`; migrate legacy single `profile.json` via chat instructions.

### C. Installer
- Fix `{USER_ROOT}` to `…/resume-tailor` (not platform root).
- Non-interactive flags: `--platform`, `--location`, `--resume`, `--install-deps`, `--yes`.
- Re-enable resume file import via `extract-from-resume.mjs` when path given.
- Portfolio/LinkedIn placeholders from profile or generic examples — never Mike’s URLs.

### D. Release & verify
- Bump `1.1.0`, tag `v1.1.0`, GitHub Action → npmjs.
- Local: `npx @mikehenken/create-resume-tailor@1.1.0 --platform claude --yes …`
- Claude CLI: `claude -p` smoke test that skill/agent/profile layout exists and agent understands multi-profile rules.

## Out of scope for v1.1
- Claude Cowork marketplace packaging (follow-up once Claude install is proven).
- Migrating existing Cursor `~/.cursor/resume-tailor/tailors/*` automatically (document chat migration only).
